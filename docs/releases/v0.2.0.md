# Release v0.2.0 — 2026-07-04

## 1. Resumen ejecutivo

Esta entrega transforma la demostración visual v0.1 en un MVP full-stack persistente. MongoDB pasa a ser la fuente de verdad; el cliente requiere identidad autenticada y todas las escrituras críticas aplican permisos por rol y generan auditoría.

## 2. Estado funcional

Disponibles: login, sesiones JWT, roles, alta/edición de empleados, direcciones, horarios, overtime, evaluación de elegibilidad, solicitudes diarias, confirmación/cancelación, excepciones, aprobación, planificación manual y automática, vehículos, conductores, asignaciones, aprobación de rutas, abordaje, protección contra duplicados, ad hoc justificado, dashboard, reglas y auditoría.

La interfaz principal consume dashboard, empleados, solicitudes, rutas, confirmaciones, aprobación de planes, alta de empleados y abordaje desde la API. El selector ficticio de roles fue eliminado: la experiencia depende del usuario autenticado.

## 3. Cambios

### Añadido

- API Express con prefijo `/api` y health check.
- Diez colecciones MongoDB con índices de integridad.
- Autenticación JWT y bcrypt.
- Nueve roles con autorización en servidor.
- Motor inicial de elegibilidad configurable.
- Planificador por zona/capacidad.
- Validación de abordaje y bloqueo de duplicados.
- Auditoría antes/después para acciones sensibles.
- Login y cierre de sesión en cliente.
- Docker Compose, variables de ejemplo y seed reproducible.
- Plantilla obligatoria para futuros releases.

### Modificado

- Dashboard y listados ya no usan métricas estáticas.
- Acciones principales persisten mediante la API.
- Vite mantiene selección automática de puerto y proxy `/api`.
- npm es el único gestor soportado.

### Eliminado

- Selector de rol simulado.
- Dependencia operativa del archivo de mocks para iniciar la aplicación.
- Configuración fija de puerto del cliente.

## 4. Arquitectura y decisiones

Se eligió MongoDB porque las entidades operativas evolucionan con rapidez, las rutas contienen conjuntos variables de pasajeros/paradas y el MVP necesita iteración de esquema sin sacrificar índices. La lógica crítica permanece en servicios HTTP; el cliente no decide elegibilidad ni autorización.

JWT reduce estado de infraestructura para el MVP. El token se almacena en localStorage; antes de una exposición pública se recomienda migrar a cookie HttpOnly con refresh tokens y rotación.

## 5. Datos y actualización

No existe migración desde v0.1 porque sus datos eran efímeros. Ejecutar `npm run seed` reemplaza por completo la base indicada en `MONGODB_URI`; por tanto, solo debe usarse en desarrollo o un entorno inicial vacío.

El seed crea ocho usuarios, siete empleados, cuatro vehículos, un conductor, una ruta, horarios/solicitudes del día, tres reglas y un evento de auditoría. Contraseña temporal común: `ViaDemo2026!`. Debe cambiarse antes de usar datos reales.

## 6. API

Se publican 25 operaciones documentadas en `docs/API.md`. Todas las escrituras validan entrada y devuelven errores estructurados. No se versionó aún la URL (`/api/v1`); queda planificado antes de integraciones externas.

## 7. Seguridad y permisos

Los permisos se validan en servidor, no en la visibilidad del menú. Los secretos quedan fuera del repositorio mediante `.env`. CORS, Helmet, hashing de contraseñas y auditoría están activos. Pendientes para producción pública: rate limiting distribuido, refresh tokens, restablecimiento de contraseña, MFA y gestión externa de secretos.

## 8. Operación y despliegue

1. Copiar `.env.example` a `.env` y reemplazar `JWT_SECRET`.
2. Ejecutar `docker compose up -d mongo`.
3. Ejecutar `npm install`.
4. Ejecutar `npm run seed` solo en la instalación inicial.
5. Ejecutar `npm run dev:all`.
6. Confirmar `GET http://localhost:4000/api/health`.
7. Abrir la URL indicada por Vite.

Rollback: detener API/cliente, restaurar backup MongoDB previo y desplegar el tag anterior. Esta versión no cambia datos anteriores porque no existían datos persistentes.

## 9. Pruebas y evidencia

Resultados ejecutados en Windows, Node.js 24 y MongoDB local:

- `npm install`: 219 paquetes auditados, 0 vulnerabilidades reportadas.
- `npm run build`: 4,577 módulos transformados; build Vite exitoso.
- Carga directa de módulos API: exitosa (`API_MODULES_OK`).
- `npm run seed`: base creada con usuarios, empleados, horarios, flota, ruta y reglas.
- `npm run test:api`: 5/5 pruebas aprobadas en 2.95 s.
- Health check: 200.
- Endpoint privado sin sesión: 401 `AUTH_REQUIRED`.
- Login de operaciones: 200 y JWT válido.
- Dashboard con MongoDB: 200 y métricas/rutas persistidas.
- Escritura fuera del rol: 403 `FORBIDDEN`.

Pendientes automatizados: confirmación/cancelación, aprobación de ruta, escaneo permitido y duplicado. Los endpoints fueron implementados, pero deben sumarse al suite en v0.2.1.

## 10. Limitaciones y deuda técnica

- La importación masiva de CSV todavía debe conectarse a un parser/cola; hoy los horarios se registran por API.
- El modo offline del conductor requiere IndexedDB y sincronización idempotente; la API ya acepta `offlineId`.
- El agrupamiento usa zona y capacidad, no optimización geoespacial avanzada (fuera del MVP original).
- Reportes PDF/CSV y envío automático al proveedor están modelados pero no cuentan con worker.
- Faltan recuperación de contraseña, refresh token y MFA.
