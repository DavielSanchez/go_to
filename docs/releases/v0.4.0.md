# Release v0.4.0 — Separación frontend/backend

Fecha: 5 de julio de 2026  
Estado: lista para piloto  
Tipo: reorganización estructural sin cambio funcional

## Objetivo

Dar una lectura inmediata de la arquitectura mediante dos límites físicos claros, manteniendo una instalación y una orquestación únicas desde la raíz.

## Estructura resultante

```text
GO_TO/
├── frontend/
│   ├── index.html
│   ├── vite.config.js
│   └── src/
├── backend/
│   ├── routes/
│   ├── tests/
│   ├── app.js
│   ├── index.js
│   ├── models.js
│   └── seed*.js
├── docs/
├── package.json
├── docker-compose.yml
└── .env
```

## Cambios realizados

- Se trasladó todo el cliente React, estilos, HTML y configuración de Vite a `frontend/`.
- Se trasladó la API, modelos, rutas, seeds y pruebas a `backend/`.
- Se conservaron dependencias y lockfile en la raíz para evitar instalaciones duplicadas y mantener el MVP sencillo.
- Se actualizaron todos los scripts raíz a las nuevas ubicaciones.
- No se cambiaron endpoints, contratos, colecciones, roles, credenciales ni reglas de negocio.
- El proxy de desarrollo continúa enviando `/api` y `/socket.io` al puerto 4000.
- Vite continúa seleccionando automáticamente un puerto disponible.

## Comandos compatibles

| Comando | Resultado |
|---|---|
| `npm run dev` | Ejecuta únicamente `frontend/` con Vite |
| `npm run dev:api` | Ejecuta `backend/` con recarga |
| `npm run dev:all` | Ejecuta frontend y backend simultáneamente |
| `npm run build` | Genera `frontend/dist/` usando el cargador estable de configuración de Vite |
| `npm run preview` | Sirve el build del frontend |
| `npm start` | Inicia la API en modo normal |
| `npm run seed` | Carga datos base y casos de piloto |
| `npm run test:api` | Ejecuta pruebas de integración del backend |

## Migración para desarrolladores

No se requiere reinstalar dependencias ni modificar `.env`. Los imports internos mantienen sus rutas relativas porque cada árbol se movió completo. Cualquier script externo que referencie directamente `src/` o `server/` debe actualizarse a `frontend/src/` o `backend/`, respectivamente.

## Compatibilidad y reversibilidad

La reorganización no migra datos y no escribe sobre MongoDB. El volumen `via_mongo_data` permanece intacto. Volver a v0.3.2 solo requiere restaurar la estructura previa del código; la base es compatible.

## Validación requerida

- Ejecutar `npm run seed`.
- Ejecutar `npm run test:api` y comprobar 13 pruebas aprobadas.
- Ejecutar `npm run build` y comprobar salida en `frontend/dist/`.
- Iniciar `npm run dev:all` y validar login y `/api/health`.
