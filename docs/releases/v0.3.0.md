# Release v0.3.0 — Preparación de piloto

## Resumen

Esta entrega aplica la especificación de correcciones para piloto. El BMS de siete dígitos pasa a ser el identificador operativo y el QR codifica ese valor. Se incorpora aislamiento por tenant, se elimina el proveedor y se restringe el abordaje exclusivamente al conductor.

## Cambios

- Tenant obligatorio en entidades operativas y auditoría.
- Login exige empresa; JWT incluye tenant y un plugin Mongoose filtra consultas y escrituras.
- BMS validado con siete números y unicidad por tenant.
- QR SVG real en el portal del empleado.
- Confirmación y cancelación persisten mediante API.
- Decisión de excepciones con comentarios, auditoría y notificación.
- Abordaje exclusivo del conductor, búsqueda por BMS, duplicados y ad hoc justificado.
- Inicio de viaje con warning de pendientes, confirmación, responsable, fecha y cantidad faltante.
- Notificaciones persistentes con leído/no leído.
- Reportes resumidos desde MongoDB.
- Auditoría global solo para administrador.
- Rol proveedor eliminado del esquema y seed.
- Tenant piloto `caribe`, site `SDQ-01` y datos BMS.

## API añadida

- `POST /api/pilot/requests/:id/decision`
- `POST /api/pilot/routes/:id/start`
- `GET /api/pilot/notifications`
- `POST /api/pilot/notifications/:id/read`
- `GET /api/pilot/audit`
- `GET /api/pilot/reports/summary`

## Seguridad y tenancy

El contexto del tenant se establece tras verificar JWT. El plugin Mongoose agrega el tenant a consultas, agregaciones y documentos nuevos. Operaciones y administrador no están autorizados a abordar; todo el router de abordaje exige `driver`.

## Migración

`npm run seed` elimina los datos del entorno configurado y crea el tenant piloto. No debe ejecutarse en una base que contenga información que deba conservarse. Acceso inicial: empresa `caribe`, contraseña `ViaDemo2026!` y correos impresos por el seed.

## Evidencia

- 248 paquetes auditados; cero vulnerabilidades reportadas.
- Build Vite exitoso: 4,584 módulos.
- Seed multitenant exitoso.
- Suite API actualizada para login con tenant.

## Brechas antes del piloto real

- `html5-qrcode` está instalado, pero falta activar la cámara en el componente y probar dispositivos físicos.
- Falta centralizar navegación declarativa para 404 y ocultamiento total de enlaces por permiso.
- Importaciones masivas, editor completo de rutas/paradas y exportaciones requieren sus pantallas finales.
- Socket.IO está instalado, pero las notificaciones aún se consultan por API; falta emisión en tiempo real.

Estas brechas impiden etiquetar v0.3.0 como piloto final. Deben cerrarse antes de incorporar usuarios reales.
